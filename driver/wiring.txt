AQUACULTURE - HARDWARE REFERENCE / PHASE 2C
===========================================
This folder is provided for future hardware setup. Nothing in this release was
flashed to an Arduino or tested with the five physical sensors. The existing
backend sensor and RBS scoring logic have not been changed.

CURRENT PROJECT LAYOUT
  AquaCulture/client/       Website templates, CSS, JavaScript
  AquaCulture/server/       Flask + Socket.IO backend
  AquaCulture/database/     aquaculture.db and media/{species,predictions,thumbnails}
  AquaCulture/driver/       Arduino Nano sketch and this wiring reference
  AquaCulture/.env          Host and device configuration (never publish secrets)

ARDUINO NANO (classic 5V ATmega328P) - PROPOSED CONNECTIONS
  Temperature DS18B20 DATA            D2, 4.7k pull-up to its VDD
  pH conditioning board analog OUT    A0
  Dissolved oxygen SEN0237-A A        A1
  Dissolved oxygen SEN0237-A +        5V (converter board; verify label)
  Dissolved oxygen SEN0237-A -        GND
  Turbidity conditioning analog OUT   A2
  MQ-137 AMMONIA GAS module analog OUT A3 (must stay dry, above water)
  Analog conditioning board GND       Common Arduino Nano GND
  Arduino USB                          Host computer / Raspberry Pi USB

Supply each sensor board according to its OWN manufacturer specification.
Do not connect Nano's 5V outputs directly to Raspberry Pi GPIO. Confirm the
modules' supply requirements and current draw; MQ-137 heater requires an
adequately rated supply. SEN0237-A probe connects to its BNC converter and
requires proper membrane preparation and calibration. Use protective equipment
and the manufacturer's chemical-handling instructions for DO filling solution.

ARDUINO FIRMWARE - nano.ino
  Reference sketch recovered from the preceding AquaCulture development ZIP.
  Arduino IDE: board Nano, processor ATmega328P (Old Bootloader if clone).
  Install Arduino libraries: OneWire, DallasTemperature.
  Serial: 115200 baud, newline-delimited JSON.
  The sketch intentionally emits NULL for uncalibrated analog channels.
  Calibration flags/coefficients in the sketch are NOT set for actual hardware.
  It emits 'ammonia_gas_ppm'. The current legacy backend sensor parser uses
  its own ammonia aliases; this mapping MUST be reviewed in the future
  hardware integration phase, with approval before modifying sensor/RBS logic.
  DS18B20 and DO sensor timing also need actual measurement validation.

  Verify class names, input dimensions, NCNN runtime and any model manifests
  before enabling inference. Files are intentionally absent in this update.

CAUTIONS
  - MQ-137 measures gaseous ammonia, NOT dissolved water ammonia.
  - No calibrated gas-vs-water equivalence exists in this release.
  - RBS three-of-five gate and current ammonia contribution were not modified.
  - Sensor calibration, BLE provisioning and Raspberry Pi deployment remain
    future hardware-phase tasks.
